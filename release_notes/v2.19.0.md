## Highlights

v2.19.0 fixes a louvered roof's up/down controls, which bound to a position axis that cover type never declares — the tile showed a stale open/closed reading and could send a move command the integration rejects outright. The floor chip in Minimum Mode now names the slot holding a cover open, the same name the more-info dialog has always shown, instead of a bare percentage. And when the sun sits in a blind spot the integration can't yet publish geometry for, the sky compass says so directly rather than drawing an unbroken field-of-view band that reads as unobstructed tracking.

## Added

- **Minimum Mode's floor chip now names the slot holding the cover open** — the chip rendered only a glyph and a percentage, so a cover held by a named custom position slot lost the context the more-info dialog already showed for that same slot. `resolveActiveMinModeFloor()` has always read the slot's `sensor_name` and returned it; `floorChipTpl()` — its only consumer — never read the field. The field was retyped from `label` to `name: string | null`, dropping an internal `#N` fallback nothing depended on, and an absent `sensor_name` now coalesces to `null` rather than `undefined`. An unnamed slot still renders the bare percentage. Thanks to environ314 for the request. Refs #278.

## Fixed

- **Louvered-roof (tilt-only) cover controls now bind to the axis the cover actually has** — a tilt-only cover type publishes only a slat axis, but the card synthesized a position axis anyway: it gated open/closed state on a position the entry never reports and could send a move command the integration rejects outright. `resolveAxes()` now reads the entry's declared leading axis for its target-sensor role, and two new helpers — `hasPositionAxis()` and `primaryAxisFor()` — gate the tile's `%` readout, its position rail, the target marker and the go-to-target button on whether the entry actually has a position axis, and drive the ↑/↓ buttons off the axis it does have. The dialog's cover row still shows its name, state and mismatch icon on a tilt-only entry; only the position track and marker are withheld. Thanks to Olivier6767 for reporting. Refs #277.

- **The sky compass now says when the sun is in a blind spot it can't draw** — `decision_trace` has published an `in_blind_spot` attribute since the trace landed, but nothing read it, so the compass drew an unbroken field-of-view band exactly when the integration was ignoring the sun. New `_decisionTraceAttrsFor()` and `_blindSpotActiveFor()` methods read the attribute; `EntryOverlay` gains `blindSpotActive` and `hasBlindGeometry` fields, and `showBlindActive()` renders a "Blind spot active" indicator — a status badge when several windows are listed, a legend row when there is just one — only when blind-spot visuals are on, the sun is in the spot, and there's no wedge geometry to draw — so it never doubles up with an actual wedge. Ships with a new `compass.blind_spot_active_tooltip` string in English, German and French. The missing geometry itself is an integration-side defect, not something this card can fix — this is its graceful degradation for that state. Thanks to m0r0c0ns for reporting. Refs #274, #269.

## Compatibility

- Home Assistant 2024.1+ (no change)
- Adaptive Cover Pro integration: v2.22.1+ baseline (unchanged)
- No config migration needed — all three changes are backward-compatible; no config option defaults changed.

## Install / Upgrade

Through HACS, update to v2.19.0. A browser restart is not required.

Home Assistant caches Lovelace ES modules aggressively. After updating, bump the `?v=2.19.0` query string on your Lovelace resource URL so the browser picks up the new bundle. A hard refresh alone will not do it.
