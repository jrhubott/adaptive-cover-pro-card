## Highlights

v2.20.0 adds a climate on/off toggle to group tiles: enable the new `show_climate` config option and a toggle appears next to the existing automation control, showing the rolled-up climate state of the group's member covers. The four separate position and tilt rail sliders across dialog and dense views now share one `RailTrack` component instead of duplicating drag handling four times over, and the tile card's min-mode floor chip finally shows the slot's configured name instead of one derived from its underlying sensor.

## Added

- **Group climate toggle** — group tiles can show an on/off toggle for member covers' climate mode. Enable it with the new `show_climate` config option (default `false`) on the card and tile card configs. The toggle sits in `acp-group-controls-row` next to the existing automation toggle and binds to the integration's `group_climate_mode_switch` entity role. It's off by default, so nothing changes on existing dashboards until you turn it on. (#225, #286, #287, #288)

## Changed

- **Position and tilt rail sliders consolidated** — the dialog and dense group views previously rendered four separate track components, one per axis and density. They now render through a single `RailTrack` element, with pointer capture, drag preview, and commit handling centralized in a new `RailGestures` reactive controller, and fill/marker rendering shared through `renderRailFill()` and `railFillStyles`. Dragging a cover's position or tilt behaves the same as before; the four implementations just stopped drifting independently. (#283, #284, #285, #289, #290, #291)

## Fixed

- **The min-mode floor chip names its slot, not its sensor** — on the tile card, the chip now reads the active custom-position slot's `custom_name` field (surfaced on the decision trace as `custom_position_active_slot_name`, via `findActiveCustomPositionSlot()`), so it shows the name you gave the slot rather than one derived from the underlying sensor entity. On integrations older than v2026.8.0, which don't send `custom_name`, the chip falls back to its previous sensor-derived name. (#278, #293)

## Compatibility

- Home Assistant 2024.1+ (no change)
- Adaptive Cover Pro integration: v2.22.1+ baseline (unchanged)
- The floor chip's slot-naming fix needs integration v2026.8.0+ for the slot's `custom_name` field. Earlier integration versions keep working through the existing sensor-derived fallback.
- The group climate toggle needs the `group_climate_mode_switch` entity role, present from integration v2026.8.0+. On older integrations, `show_climate` has no effect: the toggle is simply not shown.

## Install / Upgrade

Through HACS, update to v2.20.0. A browser restart is not required.

Home Assistant caches Lovelace ES modules aggressively. After updating, bump the `?v=2.20.0` query string on your Lovelace resource URL so the browser picks up the new bundle. A hard refresh alone will not do it.
