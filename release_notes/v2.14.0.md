## Highlights

v2.14.0 adds a way to push out an active manual override without leaving the tile, and fixes covers that never report a position. While an override is running, the tile's badge grows a clock button that opens a dialog to extend it — quick-pick times drawn from the same solar forecast the card already reads, relative "add time" chips, or a custom end time. Separately, covers that sit at `unknown` forever, like an assumed-state Somfy RTS blind, were being treated as offline: dimmed, uncontrollable, labeled "Unavailable." They now render and behave like any other live, no-feedback cover.

## Added

- **Extend an active manual override from the tile badge** — the badge's new extend action opens `ExtendOverrideDialog`, offering quick-pick times built by `buildOverridePresets` from the `position_forecast` sensor's upcoming events, relative "+15m/+30m/+1h/+2h" chips, and a custom time input. Confirming calls the integration's `adaptive_cover_pro.engage_manual_override` service with an explicit `end_time`. Refs #229, PR #230.

- **Extend sits next to Resume, not in place of it** — the tile badge's `extendable` action renders alongside the existing `resumable` one, so a single badge can push the deadline out or hand control back to automatic. On integrations older than v2026.7.0, `hasEngageManualOverride` detects the missing service and Extend simply doesn't appear; Resume still works. Refs #229, PR #230.

- **Preset times fall back to sunrise/sunset when the forecast sensor runs dry** — `nextSolarEvents` computes the next sunrise and sunset locally and tops up the preset list late in the day, so the extend dialog isn't left with a single chip. Refs #229, PR #230.

## Fixed

- **Covers that never report a position stay controllable** — a cover with no position feedback, such as a one-way Somfy RTS blind, can sit at HA's `unknown` state forever while remaining fully reachable. Before this fix, the tile treated `unknown` the same as `unavailable`: dimmed, disabled controls, "Unavailable" label. `isOffline` now checks only for `unavailable`/missing, while the broader `isUnavailable` (also covering `unknown`) is reserved for gating raw `current_position`/`current_tilt_position` attribute reads. An `unknown` cover now keeps live controls, shows a real state via `formatCoverState` instead of a blank tile, and its icon color runs through `coverStateColor`'s normal cascade in the inactive (grey) tier rather than the unavailable tier. Refs #232.

## Compatibility

- Home Assistant 2024.1+ (no change)
- Adaptive Cover Pro integration: v2.22.1+ baseline (unchanged). Extending an override additionally requires integration v2026.7.0+, where `adaptive_cover_pro.engage_manual_override` ships — on older integrations the Extend button doesn't render, and Resume continues to work as before.
- No config migration needed — existing card configs load unchanged

## Install / Upgrade

Through HACS, update to v2.14.0. A browser restart is not required.

HA caches ES modules aggressively. After updating, bump the `?v=X.Y.Z` query string on your Lovelace resource URL to ensure browsers pick up the new bundle. A hard-refresh alone is not sufficient.
