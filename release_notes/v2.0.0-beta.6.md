# v2.0.0-beta.6

## Highlights

This beta finishes the service-routing work started in beta.5: stop now travels through `adaptive_cover_pro.stop` rather than `cover.stop_cover`, so every tile-card action — open, close, slider, and stop — is recognized as ACP-originated when `manual_ignore_external` mode is on. It also fixes the most-reported display bug from beta.3 onward: while a manual override is active, the tile card now shows the cover's real position and a "Manual" badge instead of the calculated target and the winning pipeline handler. If you use manual overrides or rely on `manual_ignore_external`, these two changes are what to focus on in this beta.

## Changed

- **Tile-card stop button now routes through `adaptive_cover_pro.stop`** — `_stopCover` in `src/adaptive-cover-pro-tile-card.ts` previously called `cover.stop_cover`; it now calls `adaptive_cover_pro.stop`. This matches the routing PR #70 applied to open, close, and slider writes, and means `manual_ignore_external` mode on the integration side correctly treats a stop command from the card as ACP-originated rather than external. Requires the integration-side `adaptive_cover_pro.stop` service (tracked in jrhubott/adaptive-cover-pro#456). (#71)

## Fixed

- **Tile card shows real cover position while a manual override is active** — the rendered position label was reading from the integration's `cover_position` sensor (the calculated target), not from the cover entity's live `current_position` attribute. A new `_liveCoverPosition` lookup in `src/adaptive-cover-pro-tile-card.ts` now takes priority for the display value, so the percentage shown matches what the cover is physically at. (#73)
- **"Manual" badge now appears whenever an override is active, regardless of pipeline winner** — the badge previously derived its label purely from the decision-trace winner, so it showed a solar or custom-position chip even when `manual_override` was active. `TileBadge` in `src/components/tile-badge.ts` now accepts a `manualActive` property; when it is `true` and the winner is anything other than `force`, the badge renders "Manual". (#73)

## Beta testing

Bump the Lovelace resource URL to `?v=2.0.0-beta.6` in Settings → Dashboards → Resources — HA caches ES modules aggressively and a hard-refresh alone will not pick up the new bundle.

- **Stop routing**: while a cover is moving, press the stop button on the tile card and confirm in the HA logbook that the service call is `adaptive_cover_pro.stop`, not `cover.stop_cover`. Requires integration `adaptive_cover_pro.stop` service from jrhubott/adaptive-cover-pro#456.
- **Live position during override**: trigger a manual override so the real position diverges from the calculated target, then check that the percentage shown on the tile card tracks the cover's actual position. The "Manual" badge should be visible at the same time, even if the decision-trace winner is a solar or custom-position handler.

## Compatibility

- Home Assistant 2024.1+
- **Adaptive Cover Pro integration `v2.22.1-beta.3` or newer required** — this beta depends on integration-side entity and attribute additions. Earlier integration versions will cause the tile card and dialog to degrade or show empty state.
