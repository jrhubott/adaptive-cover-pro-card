## Highlights

v2.15.0 turns most of the tile's read-only surfaces into ones you can act on directly. The new History card puts 24 hours of cover activity, an event feed, and context bands for sun, glare, and manual override right on the dashboard. The tile's position and tilt bars are now drag-to-set instead of display-only, and the Cover Group tile grows a full control surface — scene selection, lock, member automation, and override clearing — that previously meant opening the integration itself.

## Added

- **History card charts a day of cover activity** — the new `AdaptiveCoverProHistoryCard` renders `HistoryView` plus a `HistoryDialog`, with a visual editor in `AdaptiveCoverProHistoryCardEditor`, backed by new `activity.ts`, `logbook.ts`, `event-timeline.ts`, and `history-stats.ts` libraries. It plots 24h of position history next to an activity feed and event buffer, with context bands for sun-in-FOV, glare, and manual override, along with move-count and position-change stats. Refs #245, #246.

- **Cover Group tile gets a full control surface** — `GroupControlsRow`, `GroupMemberRow`, and `GroupDialog` add scene selection, a lock toggle, a member-automation toggle, a clear-overrides button, and per-member rows to the group tile and its dialog. Five config options gate them: `show_scene_select`, `show_lock`, `show_automation`, `show_clear_overrides`, and `show_member_badges`, all defaulting to true. Existing group tiles pick up the full surface with no config change. Refs #241, #242.

- **Drag-to-set position and tilt** — the tile's `cover-bar.ts` and `tilt-bar.ts` components respond to click-and-drag now, showing a live percentage while you drag instead of only displaying the current value. The commit goes through `setAxes()`, which feature-detects the integration's `set_axes` service and falls back to the legacy per-axis `set_position` / `set_tilt` calls on older integration builds. Interactive drags deliberately omit `force`, so your existing manual-override semantics are preserved. Refs #231, #235, #238, #239.

- **Composite tile names** — `name` now also accepts an array of `AcpNamePart` entries (`{type: 'entry' | 'area' | 'text', text?}`), so a tile's title can combine the entry name, its assigned area, and literal text in any order. Existing plain-string `name` values keep working unchanged. Refs #247, #249.

- **Group Automation button reflects member status** — `rollupMemberAutomation()` reduces each group member's automation state to a `MemberAutomationStatus` of `all`, `some`, `none`, or `unknown`, coloring the group tile's Automation button so a partially-automated group reads differently from a fully-on or fully-off one. Refs #248.

## Changed

- **Tile buttons and chrome now match HA's native tile spec** — the shared `acp-cover-move-buttons` row picks up HA's button layout and icon sizing, and a new `icon_tap_action` config (default `none`) controls whether the cover icon renders as a tappable pill, matching stock HA cover tiles that show no icon circle by default. Refs #250, #251.

## Fixed

- **Tilt and position render in the logical frame** — `resolveAxes()` and `positionAxisInverted()` normalize both against axis inversion and awning behavior, so `cover-bar.ts` and `tilt-bar.ts` show the orientation a user expects regardless of how the underlying cover reports its axis. Refs #234, #236, #237, #240.

- **History and forecast-strip curves step across recorder gaps instead of drawing a diagonal** — recorder history is a step function, not a continuous line. `stepExpand()` and `toBands()` now expand samples to step edges before plotting, and the forecast strip's actual-position overlay adds `clampToWindow()` to pin the recorder's pre-window carry-in sample, plus `isoToPoints()` and `valueAt()`, the same hold-lookup the History card uses. Refs #253, #254, #255, #256.

## Compatibility

- Home Assistant 2024.1+ (no change)
- Adaptive Cover Pro integration: v2.22.1+ baseline (unchanged)
- No config migration needed — existing card configs load unchanged. New group options default to true and `icon_tap_action` defaults to `none`, so upgrading changes nothing until you opt into the new controls.

## Install / Upgrade

Through HACS, update to v2.15.0. A browser restart is not required.

HA caches ES modules aggressively. After updating, bump the `?v=X.Y.Z` query string on your Lovelace resource URL to ensure browsers pick up the new bundle. A hard refresh alone is not sufficient.
