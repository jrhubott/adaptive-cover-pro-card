## Highlights

v2.19.1 fixes a tile card action that silently stopped firing. An `icon_tap_action` — or any of `tap_action`, `hold_action`, `double_tap_action` — configured through the card's own `ha-selector` editor's `ui_action` selector could do nothing at all on Home Assistant 2024.8 and later: HA renamed its "call a service" action vocabulary that release, and the pinned `custom-card-helpers@2.0.0` this card dispatches through never learned the new spelling.

## Fixed

- **Tile card actions configured through the visual editor now fire on HA 2024.8+** — HA's `ha-selector` renamed `call-service` to `perform-action` (and `service`/`service_data` to `perform_action`/`data`) in 2024.8, but `custom-card-helpers@2.0.0`'s `handleAction()` — the only thing this card calls to dispatch `tap_action`, `hold_action`, `double_tap_action`, and `icon_tap_action` — reads only the old `service` and `service_data` fields and silently no-ops on anything else. A new `normalizeActionConfig()` helper (with `ActionConfigInput`/`RawServiceActionConfig` types alongside it) rewrites both vocabularies to the `call-service` shape `handleAction()` understands, applied once where `_config` is assigned. `custom-card-helpers` has no newer published version to bump to. Thanks to JonasKemmer for reporting. Refs #281.

## Compatibility

- Home Assistant 2024.1+ (no change)
- Adaptive Cover Pro integration: v2.22.1+ baseline (unchanged)
- No config migration needed — existing configs already spelled `call-service` with `service`/`service_data` continue to work unchanged.

## Install / Upgrade

Through HACS, update to v2.19.1. A browser restart is not required.

Home Assistant caches Lovelace ES modules aggressively. After updating, bump the `?v=2.19.1` query string on your Lovelace resource URL so the browser picks up the new bundle. A hard refresh alone will not do it.
