# v2.0.0-beta.2

## Highlights

This beta rounds out the tile card's visual design to match the native HA tile-card aesthetic. The position slot now shows a localized state label alongside the percentage ("Open · 12%"), the cover icon carries a small motion-sensor badge when motion is active, the `detailed` layout mode restructures the tile into three clean rows, and the more-info dialog header gains direct links to the integration's config page and the HA device page. If you tested beta.1, upgrade and focus feedback on how the tile looks at different widths in `detailed` mode and whether the motion overlay fires at the right times.

## Added

- **`show_state` config option** — renders the localized cover state ("Open", "Closed", "Opening", etc.) next to the position percentage, joined with ` · `. Uses `hass.formatEntityState` when available and falls back to the standard cover translation key; defaults on. Set `show_state: false` to suppress it. Added in `src/lib/formatters.ts` as `formatCoverState`.
- **Motion-sensor overlay on the cover icon** — when `motion_status_sensor` reports `motion_detected` or `timeout_pending`, an `mdi:motion-sensor` glyph appears in the top-right corner of the tile's cover icon. Color uses `--warning-color`. Controlled by `show_motion_icon` (default on). The `title` attribute distinguishes the two active states ("Motion detected" vs. "Motion timeout pending").
- **Header buttons in the more-info dialog** — two icon buttons sit in the dialog header beside the close button. `mdi:tune-variant` navigates to the integration's config page; `mdi:cog` navigates to the HA device page and is shown only when `discoverEntities` captured a `device_id`. Both use HA's `pushState` + `location-changed` pattern and close the dialog.
- **`device_id` in `DiscoveredEntities`** — `discoverEntities` now captures the first `device_id` found on a matched entity registry entry and exposes it as `DiscoveredEntities.device_id`.

## Changed

- **`layout: 'two-line'` renamed to `layout: 'detailed'`** — the old `two-line` option is replaced by `detailed`, which puts the entry title on row 1, state · position and the ↑■↓ controls on row 2, and the contextual badge on a collapsible row 3 (row 3 is omitted from the grid when there is no badge or Resume button to show). The `layout` type in `AdaptiveCoverProTileCardConfig` is now `'one-line' | 'detailed'`.
- **Control buttons use `ha-icon`** — the unicode ▲ ■ ▼ glyphs are replaced with `mdi:arrow-up`, `mdi:stop`, and `mdi:arrow-down` `ha-icon` elements, sized and styled to match HA's native tile-card buttons in `detailed` mode.

## Beta testing

Install via HACS using the "show beta versions" toggle. After installing, bump the resource URL cache-buster in Settings → Dashboards → Resources to `?v=2.0.0-beta.2` — HA aggressively caches Lovelace module URLs and a hard-refresh alone will not pick up the new bundle. Priority feedback areas: tile rendering at different dashboard widths in `detailed` mode, the motion overlay firing correctly for `motion_detected` and `timeout_pending` states, and the dialog header navigation buttons on both desktop and mobile.

## Compatibility

- Home Assistant 2024.1+
- **Adaptive Cover Pro integration `v2.22.1-beta.3` or newer required** — this beta depends on integration-side entity and attribute additions. Earlier integration versions will cause the tile card and dialog to degrade or show empty state.
