## Highlights

v2.18.0 closes a blind spot that was strictly a card bug: a window's second or third blind-spot slot, fully configured on the integration side, never drew on the sky compass, because the card only ever read `blind_spot_range`, the attribute carrying slot 1 alone — it now reads the full `blind_spot_ranges` list. A one-way awning that reports no position stops reading as a permanent "unavailable" warning; HA's own state wins over a missing number. Everything else is new: the battery readout on a cover or group dialog is now a link into HA's History panel with every battery source in the entry preloaded, a Cover Group roster gets its own per-card order, visibility and naming through one sortable list in the editor, a layered two-rail entry whose two fabrics disagree — a day/night shade, a dual-panel cover — says so in its state line instead of describing only one of them, and every position command now paints a striped band and marker showing where the cover is headed until it arrives.

## Added

- **The battery readout is now a link to HA's History panel** — clicking it carries every battery source in the entry along, deduped so two covers sharing one physical device's battery sensor don't show the same row twice. The cover more-info dialog and the group dialog now share one `acp-battery-indicator` component (`BatteryIndicator`) instead of two copies of the same logic, so the group dialog gets the same worst-cell glyph and named-battery tooltip the cover dialog already had. Refs #272, #273.

- **A new `members` option orders, hides and renames Cover Group roster rows per card** — the editor's roster widget, previously a plain `member_names` text field, is now one sortable list: drag a row, or use the arrows, to reorder it; the eye hides a member from this card without removing it from the group; the same row still takes a name override. `applyMemberOrder()` applies the list — sorting rows by their earliest listed cover and dropping the ones `members` leaves out — using cover entity ids rather than roster row keys, because a row key only resolves to an owning entry while that cover's owner can be found, and `hiddenMemberCovers()` needs it to work for exactly the members most likely to be hidden: the unavailable ones. Hiding a member isn't only cosmetic — `restrictSnapshot()` recomputes the aggregate percentage, the aggregate open/closed/mixed state, and the N/M who-won count over the covers still shown, so a hidden cover stops speaking through the summary line too. Refs #272, #273.

- **A layered two-rail entry now says when its two fabrics disagree** — a day/night shade whose fabrics sit at open-100% and closed-50% used to read exactly like one at open-100%, because the state line only ever described the resolved cover. When `railsAreOneCover()` reports a layered pair and the two rails' state or position actually differ, the detailed-layout state line now shows both. In sync, the tile keeps the shorter line it's always had. Refs #272, #273.

- **Every position command now paints where the cover is heading until it arrives** — a rail tap, a drag release, an arrow key and the ↑/↓ buttons all funnel through the same `PendingMoves` controller, which draws a striped travel band and a diamond marker (`renderRailOverlay()`) from the live position out to the commanded one. It survives up to 60 seconds (`PENDING_MOVE_TIMEOUT_MS`) for a no-feedback cover that never reports arrival, and treats anything within 2 points of the target as arrived (`PENDING_MOVE_TOLERANCE`) rather than waiting for an exact match. The cover tile's and group tile's position bars, the dialog's `acp-cover-bar`, and `acp-axis-bar` all share the same overlay and rules; a pipeline-driven automatic move shows the same indicator via `isMovingState()`, using the tick the rail already draws as its destination. The remaining overlap between these four rails is tracked in #271. Refs #272, #273.

## Fixed

- **A blind spot configured in slot 2 or 3 finally draws** — the sky compass read only `blind_spot_range`, the integration's slot-1-only attribute, so a spot placed in either of the other two slots was configured correctly and simply never appeared. It now reads `blind_spot_ranges`, the full list, via `blindSpotBearingList()`, and drops any zero-span pair rather than drawing it as an invisible degenerate wedge. Refs #269, #272, #273.

- **A cover with no reported position stops reading as permanently unavailable** — `memberException()` used to count a null position on its own, which mislabeled every one-way, assumed-state cover: a Somfy-style RTS awning has no `current_position` to publish, so the group sensor had nothing there and the tile called it unavailable forever. The check now defers to HA's own state when there is one, and only falls back to the null-position rule when HA has no state for the entity at all. Refs #272, #273.

## Compatibility

- Home Assistant 2024.1+ (no change)
- Adaptive Cover Pro integration: v2.22.1+ baseline (unchanged)
- No config migration needed. `members` is optional; existing group tile configs load unchanged, and roster order, visibility and aggregates behave exactly as before until you set it.

## Install / Upgrade

Through HACS, update to v2.18.0. A browser restart is not required.

Home Assistant caches Lovelace ES modules aggressively. After updating, bump the `?v=X.Y.Z` query string on your Lovelace resource URL so the browser picks up the new bundle. A hard refresh alone will not do it.
