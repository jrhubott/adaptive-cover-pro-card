# v2.0.2

## Highlights

v2.0.2 is a small follow-up patch to v2.0.1. The arc fix in v2.0.1 corrected which half of the sky the window wedge traced, but a tighter corner case slipped through: when the integration reports an elevation-clipped active sun range — an interior start/end pair that doesn't span the full configured field of view — the "which arc contains the window normal" heuristic could still pick the wrong ~270° inverse arc. This patch replaces that heuristic with `clampActiveArcToFov`, a dedicated helper that projects each azimuth onto the FOV envelope and selects the correct sub-arc, handling the north-wrap case and falling back gracefully when sensors are absent.

## Fixed

- **Sky compass active arc clamped to FOV envelope** — when the integration reports an elevation-clipped active sun range (issues #85, #89), the previous arc-selection logic could pick the wide inverse arc instead of the narrow window-facing sub-arc. The fix adds `clampActiveArcToFov` to `src/lib/geometry.ts`, which projects `normalizeAzimuth`-normalized start and end azimuths onto the configured `[windowAzi − fov_left, windowAzi + fov_right]` envelope and returns the sub-arc that lies within that range. `src/components/sky-compass.ts` now calls this helper instead of re-implementing the arc decision inline (#89).
