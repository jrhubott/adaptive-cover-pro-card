# v2.0.0-beta.7

## Highlights

This beta patches two bugs that caused the card to display and send incorrect data. The tile-card and more-info-dialog badges were showing the rule's position floor for `min_mode` custom-position rules rather than the effective position the cover actually settles at — the badge now calls `resolveCustomPositionPct` to compute the correct value. The second fix corrects how service calls are shaped: `set_position` and `stop` now pass `entity_id` via HA's dedicated `target` argument rather than burying it in the service data payload, which fixes rejections on newer HA cores. If you use `min_mode` rules or saw covers not responding to slider or stop commands, these are the two things to verify.

## Fixed

- **Badge shows effective position instead of floor for `min_mode` custom-position rules** — for custom-position rules with `min_mode: true`, the rule's `position` field is a floor the cover should not go below; the actual settled position is the larger of that floor and any prior pipeline result. The badge in `src/adaptive-cover-pro-tile-card.ts` and the dialog badge in `src/components/more-info-dialog.ts` previously rendered the raw floor value. Both now call `resolveCustomPositionPct` from `src/lib/decision-summary.ts`, which computes the effective resolved position. (#77, #79)

- **`set_position` and `stop` pass `entity_id` via `target`, not service data** — `callService` calls for `adaptive_cover_pro` `set_position` and `stop` previously included `entity_id` inside the service data object. They now pass it as the dedicated HA target argument: `callService('adaptive_cover_pro', 'set_position', { position }, { entity_id })`. This matches HA's standard service-call shape and resolves cases where newer HA cores rejected the data-payload form. The same fix applies to stop calls in `src/adaptive-cover-pro-tile-card.ts` and `src/components/cover-bar.ts`. (#76, #78)

## Beta testing

Bump the Lovelace resource URL to `?v=2.0.0-beta.7` in Settings → Dashboards → Resources — HA caches ES modules aggressively and a hard-refresh alone will not pick up the new bundle.

- **`min_mode` badge**: configure a custom-position rule with `min_mode: true` and let the cover settle above the rule floor. Confirm the tile-card badge and the more-info dialog both show the effective position, not the floor value.
- **Service call shape**: trigger a cover move via the slider and a stop via the stop button. Check the HA logbook or developer tools to confirm both `adaptive_cover_pro.set_position` and `adaptive_cover_pro.stop` calls carry `entity_id` under `target`, not inside the service data.

## Compatibility

- Home Assistant 2024.1+
- **Adaptive Cover Pro integration `v2.22.1-beta.3` or newer required** — this beta depends on integration-side entity and attribute additions. Earlier integration versions will cause the tile card and dialog to degrade or show empty state.
