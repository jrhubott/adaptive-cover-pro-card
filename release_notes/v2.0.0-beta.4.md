# v2.0.0-beta.4

## Highlights

This beta ships the i18n foundation for the 2.0 card — every user-visible string is now routed through `t()` in `src/lib/i18n.ts`, and a complete draft French translation is included in `src/lib/i18n/fr.ts`. The translation is best-effort and needs a native speaker to go through it. If you speak French and use Adaptive Cover Pro, this is the release to test: set HA's language to `fr`, reload the card, and leave corrections in #64. @environ314, your review is specifically what unblocks this work. **This beta is cut from the `feature/issue-64-fr-translations` branch, not `main` — it exists to get the translations in front of reviewers before the branch merges.**

Cache-bust the Lovelace resource URL after installing: change `?v=2.0.0-beta.3` to `?v=2.0.0-beta.4` in Settings → Dashboards → Resources. HA caches ES modules aggressively and a hard-refresh alone will not pick up the new bundle.

## Added

- **`t()` translation helper** (`src/lib/i18n.ts`) — resolves a dot-separated key against a locale table, interpolates `{placeholder}` tokens, and falls back to the EN table when a key is missing in the active locale. Locale is read from `hass.locale.language` then `hass.language`, normalised to a BCP-47 base tag (e.g. `fr-CA` → `fr`).
- **EN string table** (`src/lib/i18n/en.ts`) — canonical source-of-truth for every user-visible string in the card.
- **Draft FR string table** (`src/lib/i18n/fr.ts`) — full French translation covering all keys, drafted for review by @environ314. Comments at the top of the file explain what to look for when reviewing.
- **i18n unit tests** (`tests/i18n.test.ts`) — covers key lookup, interpolation, locale fallback, and unknown-key passthrough.

## Changed

- **Every card surface now uses `t()` for UI strings** — all components (`src/components/`, card roots, editors) pass through the translation helper rather than inlining English literals. The EN table ensures existing behaviour is unchanged when HA's language is English or unsupported.

## Fixed

- **`EnDict` type no longer rejects non-EN leaf values** — the original type was derived as `typeof en` with `as const`, which locked every leaf to its exact EN string literal. Any French value immediately failed `TS2322`. The type is now `DeepStringify<typeof en>`, which enforces key structure while widening leaf values to `string`.
- **`scripts/release` ignored `--dry-run` unless it was the first argument** — the flag is now scanned from all positional arguments, so `scripts/release beta --dry-run` no longer silently performs a real release.

## Compatibility

- Home Assistant 2024.1+
- **Adaptive Cover Pro integration `v2.22.1-beta.3` or newer required** — this beta depends on integration-side entity and attribute additions. Earlier integration versions will cause the tile card and dialog to degrade or show empty state.
