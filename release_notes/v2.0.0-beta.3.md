# v2.0.0-beta.3

## Highlights

This beta is a polish pass on the tile card and forecast strip introduced in beta.1 and beta.2. The forecast strip gains interactive hover affordances — move the pointer across the curve to see a follow-along label with time, position percentage, and handler name; hover a colored event line for a richer tooltip naming the event ("Sun enters window field of view — 09:42") with a wider hit area. The strip also gets time-range and 100% axis labels so it reads without guessing the scale. The `custom_position` badge no longer repeats the "Custom ·" prefix when a named slot is shown — the badge stays narrow and consistent with how the manual badge handles its clock. And the editor now auto-selects the cover entity when a config entry manages exactly one cover. If you tested beta.2, focus feedback on the hover UX across different cover configurations and the badge display for named custom-position slots.

## Added

- **Forecast strip hover labels** — moving the pointer across `acp-forecast-strip` snaps to the nearest sample and shows a follow-along label above the curve with time, position percentage, and handler (e.g. `09:42 · 35% · solar`). A dashed vertical guide line and a dot on the curve track the snapped point. Implemented via `@pointermove`/`@pointerleave` listeners on the SVG element and a `_nearestSampleIdx` scan in `src/components/forecast-strip.ts`.
- **Richer event-line tooltips** — vertical boundary markers (`sunrise`, `sunset`, `fov_enter`, `fov_exit`) now show a human-readable description plus local time in their `<title>`, e.g. "Sun enters window field of view — 09:42". Hit area is widened to 12px via a transparent `stroke-width` overlay (`EVENT_HIT_W = 12`) so narrow dashed lines are easy to target. Cursor switches to `cursor: help` on hover.
- **Forecast strip axis labels** — three `<text>` elements annotate the strip: `100%` in the top-left corner (the full-open rail), and the start and end clock times along the bottom edge. Styled as `.axis-label` with `font-size: 9px` and `--secondary-text-color`.
- **Editor cover auto-fill** — `AdaptiveCoverProTileCardEditor` calls `_maybePrefillCover()` after loading the entity registry. When a config entry manages exactly one cover and `config.cover` is unset, it emits the single cover entity ID automatically. When multiple covers are managed and no cover is configured, a hint line reads "Leave blank to use the first managed cover automatically."

## Changed

- **`custom_position` badge drops the "Custom ·" prefix for named slots** — when `slotName` is set, `acp-tile-badge` now renders the slot name alone (e.g. "Table extension") instead of "Custom · Table extension". The `custom_position` purple color signals the kind; the prefix was redundant. Unnamed slots still render "Custom #N"; the bare "Custom" fallback is unchanged.

## Fixed

- **Forecast strip event tooltip was the raw `label` field** — tooltips now include the kind's plain-English meaning resolved through `EVENT_KIND_MEANINGS` in `src/components/forecast-strip.ts`, falling back to the raw label only when the kind is unrecognised.

## Beta testing

- Bump the Lovelace resource `?v=2.0.0-beta.3` query string in Settings → Dashboards → Resources — HA caches ES modules aggressively and a hard-refresh alone will not pick up the new bundle.
- Hover the forecast curve with covers in different states (solar controlling, manual override active, custom-position slot active) and confirm the follow-along label shows the correct handler name.
- Hover the colored event lines and confirm the tooltip reads e.g. "Sun enters window field of view — 09:42" rather than the raw `fov_enter` label.
- Check `custom_position` badges for named slots — they should now show just the slot name, not "Custom · <name>".
- Open the tile card editor on a config entry with exactly one managed cover and confirm the cover entity pre-fills; on a multi-cover entry confirm the hint text appears.

## Compatibility

- Home Assistant 2024.1+
- **Adaptive Cover Pro integration `v2.22.1-beta.3` or newer required** — this beta depends on integration-side entity and attribute additions. Earlier integration versions will cause the tile card and dialog to degrade or show empty state.
